# 语伴 · 外语学习小程序

纯前端、零后端、开箱即用的微信小程序，**以口语练习为核心**：句子/情景对话/单词跟读 + 逐词高亮(K歌字幕) + A-B复读 + 角色扮演 + 自建素材导入 + 录音回放 + 发音客观评分（可选）+ 重点复练 + **今日待练清单（清单里可直接试听，不用跳页）**，辅以单词卡片（**可按分类学新词**）、FSRS 智能复习、小测验（**优先考到期词与到期句子，结果写回复习计划**）、**听写练习（听音写词/写句，写错进复习）**、查词（**收藏夹 + 搜索历史**）、错词本、录音历史、打卡日历、**口语流利度曲线**、成就徽章（可分享打卡成绩）和进度统计。英语为主（内置 **480 词 + 120 句 + 8 组情景对话**，日语 **110 词 + 100 句 + 8 组情景对话**，均标注 CEFR 难度；**日语和英语的句子朗读都用随包离线音频**，不联网也能听），词表按「四级/六级/考研/雅思托福」+「日常/情绪/工作/财务/交通/购物/学校/家庭/身体/天气/形容词/动词…」分类筛选，结构上预留多语言扩展。发音有**四级自动降级**（有道 → 有道备源 → 百度翻译 → 同声传译合成），断网/接口挂了也不误事；**听过的句子会缓存成本地文件**，同一句再听 0 请求。

## 导入与运行

1. 打开 **微信开发者工具** → 导入项目
2. 目录选择本文件夹（`语言学习小程序`）
3. AppID 已填好真实小程序 AppID（`project.config.json` 里 `appid: wx95cccc560a35d484`）；用自己的号预览/真机调试时，开发者工具会要求你是该小程序的开发者或体验成员
4. 点击「编译」即可在模拟器里使用；**口语录音、发音评分建议真机预览**

发音使用公开 TTS 接口，**需联网**；英语主源（有道）对整句经常返回 500，会自动降级到百度翻译 TTS，再不行才用同声传译本地合成（插件 `WechatSI` 已添加，provider `wx069ba97219f66d99`，v0.3.10）。**日语不走在线合成**：353 条日语朗读（100 句 + 33 行对话 + 110 词 + 110 条例句）已预先生成为 mp3，随包发布、不联网也能听；英语的 148 条句子/台词朗读同样随包。原因与做法见「离线音频与分包」一节。录音用微信原生录音能力，需授权麦克风。网络发音下载过一次就缓存进本地（上限 1.5MB，按最久未使用淘汰），同一句再听不再联网；占的空间在「统计 → 使用设置 → 发音缓存」里能看到并一键清空。弱网下载挂 8 秒看门狗，超时自动换下一个发音源，页面上会显示「正在加载发音」。

## 离线音频与 CDN（为什么日语必须预生成、为什么 mp3 不进包）

日语整句找不到可靠的免费合成源，实测结论：

| 来源 | 日语单词 | 日语整句 |
| --- | --- | --- |
| 有道 `dictvoice` | 可以（必须带 `le=jap`，不带会返回 1920 字节静音占位文件） | 返回 0 字节 / 500 |
| 百度 `fanyi.baidu.com/gettts` | 403 | 403 |
| 微信同声传译 `textToSpeech` | 官方文档只列 `zh_CN`/`en_US` | 同左 |

百度智能云、阿里云、讯飞**都有日语 TTS**，但都需要 AccessKey 签名：密钥放前端会被反编译拿走（盗刷账单），
所以必须配后端或云函数，等于放弃「纯前端零后端」这个定位。因此这里选择**离线预生成**：

- 音频用 [edge-tts](https://github.com/rany2/edge-tts)（微软 Edge 朗读通道，免费、无需密钥）合成，
  日语 `ja-JP-NanamiNeural`、英语 `en-US-JennyNeural`
- 再用 ffmpeg 压到 16kHz / 16kbps 单声道，单条约 5–7KB
- 播放时 `audio.speak()` 先查 `utils/local-audio.js` 里有没有这个 id 的预生成音频，
  有就流播 CDN 上那一份（**不占智聆配额、不受有道 500 影响**）；
  没有对应音频的条目（自建素材、英语单词）照旧走在线降级链
- 慢速按钮对本地文件用 `playbackRate = 0.75` 变速，不额外占空间

### 音频不进代码包（为什么，以及用户听到的是哪一份）

| 位置 | 内容 | 体积 |
| --- | --- | --- |
| 主包 | 只有代码（wxml/wxss/js/json） | 约 **467KB / 2048KB** |
| Cloudflare Pages | 日语朗读 353 条（100 句 + 33 行台词 + 110 词 + 110 条例句） | 约 1.8MB（不进包） |
| Cloudflare Pages | 英语朗读 148 条（120 句 + 28 行台词） | 约 0.95MB（不进包） |

**mp3 一条都不在代码包里**：它们放在仓库的 `audio-src/ja`、`audio-src/en`（`project.config.json`
的 `packOptions.ignore` 与 `tools/validate.js` 都已排除），由 CI 发布时铺到
`https://yb.qy663.de5.net/audio/<id>.mp3`、`/audio-en/<id>.mp3`。

为什么连分包也不放：真机上两条路都被堵死了 ——

1. `InnerAudioContext` 不能直接播代码包内的 mp3：日志 `operateAudio:fail:access denied`；
2. 换成 `FileSystemManager.readFileSync` 读分包文件再复制到用户目录，真机同样读不到：
   日志 `[pkg-audio] 读不到代码包内的音频 /packageJa/ja/js001.mp3`（带不带前导斜杠都试过）。

结论：打进包既播不出来，又白占 3.8MB **上传体积**和用户**首次下载流量**（微信规定主包+分包要一起下载）。
所以现在只有一条链路：**流播 CDN → （失败）在线 TTS 链**。
`InnerAudioContext` 播网络地址不校验 `downloadFile` 白名单，因此不需要用户额外配置域名；
想让它「听过的句子断网也能听」，把 `https://yb.qy663.de5.net` 加进 **downloadFile 合法域名**即可（可选）。

代价要说清楚：**完全依赖 CDN 可达性**。CDN 挂了时，英语能退到有道/百度在线 TTS，
日语整句没有免费在线源（见上表），会提示「日语整句暂无合成发音，可点单词单独听」。

素材改动后重新生成（需要 `pip install --break-system-packages edge-tts imageio-ffmpeg`）：

```bash
node tools/dump-items.js ja /tmp/ja_items.json
python3 tools/gen-audio.py --lang ja --items /tmp/ja_items.json --out audio-src/ja

node tools/dump-items.js en /tmp/en_items.json --no-words   # 英语不预生成单词，见下
python3 tools/gen-audio.py --lang en --items /tmp/en_items.json --out audio-src/en

node tools/gen-local-audio.js    # 扫磁盘重新生成 utils/local-audio.js 清单（id → CDN 地址）
node tools/validate.js           # 主包体积、页面四件套、JSON/JS 语法
```

合成脚本会跳过已存在的文件，只补新的；`--force` 可全部重生成。
英语**不预生成单词发音**：480 词 + 480 例句 = 960 个文件约 6.5MB，而单词的在线源（有道）一直稳定，
只有整句才会挂——把包体用在真正需要的地方。

`project.config.json` 的 `packOptions.ignore` 已把 `.md`、`tools/`、`tests/`、`deploy/` 排除出包。

## 学新词的顺序（为什么先学 keep 而不是 abandon）

词库数组是字母序，原实现直接 `filter(未学).slice(0, 5)`，等于**按字母表发词**：
新用户第一天的五个词是 `abandon`(COCA 2182) / `ability`(783) / `accept`(766) /
`access`(1113) / `accommodate`(3717)，第五个词在英语语料里排三千名开外。

现在改成**高频优先**：`utils/word-rank.js` 内置 439 个英语词的词频排名（数字越小越常用），
`storage.getNewWords()` 按排名升序取词。改完之后首日五个词是
`keep`(156) / `different`(237) / `book`(241) / `continue`(293) / `create`(332)。

- 数据来源：**ECDICT**（https://github.com/skywind3000/ECDICT）的 `frq`（COCA 词频排名）字段，
  `frq` 为 0 时退回 `bnc`（BNC 排名）；两者都为 0 的超低频词不收录，排序时排在最后。
- 日语词不进这张表（没有对应的日语语料库排名），保持词库原顺序。
- 分类筛选（四级/六级/日常…）仍然生效，两个条件叠加：先在分类内过滤，再按词频排序。

## 日语逐词高亮（TinySegmenter + 真实时长对齐）

逐词高亮原来按空格切词，而日语不写空格——整句只会被当成 1 个 token，
高亮对 62 个日语句子等于失效。两处改动：

- **切词**：`utils/tiny-segmenter.js`（TinySegmenter 0.1，作者 Taku Kudo，New BSD，
  18KB 纯 JS、无依赖）把日语句子切成 `私 / は / 中国 / から / 来 / まし / た` 这种粒度；
  英语仍按空格切，行为不变。
- **对齐**：高亮时间表原本按字数加权估算。现在音频 `canplay` 后读 `InnerAudioContext.duration`
  真实时长，`highlighter.retime()` 现场重排时间表（慢速播放会按 `playbackRate` 换算成实际耗时），
  高亮不会越走越偏。
- 日语的 token 之间不补空格（`toView()` 按语种决定），英语 token 自带一个尾随空格。

第三方代码只有这一个：`utils/tiny-segmenter.js`，文件头保留了原作者与许可信息，可随时替换回上游版本；
本地只改了两处（`regexp.compile` 换成标准 `new RegExp`、末尾补 `module.exports`）。

## 性能与流畅度

针对小程序"同步 Storage 慢、setData 大列表卡"两个主要卡顿源做了优化，纯内部改动，**用法完全不变**：

- **音频只能走 CDN**：真机读不到代码包内的 mp3（`operateAudio:fail:access denied`、`[pkg-audio] 读不到代码包内的音频`），所以 mp3 不进包，统一由 Cloudflare Pages 提供（`https://yb.qy663.de5.net/audio/…`）。代价是需要联网；英语失败还能退到在线 TTS，日语整句没有免费在线源。
- **队列 id 带前缀，音频文件名用原始 id**：跟读队列里的是 `st_s001`（句子）、`dl_d003_1`（对话台词）、`sp_xxx`（自建素材），而 mp3 文件名是 `s001.mp3`、`d003_1.mp3`。`utils/local-audio.js` 的 `remoteFor()` 会把 `st_`/`dl_`/`sp_` 前缀剥掉再查一次，两个都认——早期只认原始 id，导致「情景对话」整段走在线链、真机上听不出声。
- **随包音频的真实可用路径只有 CDN**：见上一节。`https://yb.qy663.de5.net` 加进 **downloadFile 合法域名**后，发音缓存（2.5MB LRU）会把听过的句子存成本地文件，断网也能重听。
- **发音缓存**：每次听句子都要联网下载 mp3，而练一句通常是「标准音 → 慢速 → AB 复读」3~4 次，弱网下每次要等 200~400ms。现在第一次下载后复制进 `USER_DATA_PATH/tts`，之后同句直接放本地文件（0 请求），按「最久未使用」淘汰；缓存的本地文件坏了会自动删掉并退回在线重试。
- **弱网不空等**：`wx.downloadFile` 没有 timeout 参数，默认要等 60 秒才失败，期间用户看到的是「点了没反应」。现在每次下载挂 8 秒看门狗，超时就放弃当前源、降级到下一个（有道↔百度），同时把「正在加载」传给页面显示；停止/切词会取消看门狗，迟到的回调不会把已经停掉的播放又拉起来。
- **数据读取缓存**：档案信息、进度/统计/设置、口语记录、在线词库缓存都加了进程内缓存，同步读次数从上百次降到个位数（实测首页一轮刷新从约 20+ 次同步读降到 2 次）；写入即时刷新、导入/切档案自动失效，不会读到脏数据。
- **查词页增量渲染**：内置 480 词不再一次性全渲染，首屏只显示 30 条，下拉"加载更多"；搜索历史改为按"搜索键"记录，不再每敲一个字都写 Storage。
- **统计页去重读取**：设置、每日数据、掌握数等只读取一次后复用。
- **学习页不传队列**：待复习/新词的队列只在页面内部流转，setData 只传「当前这一张卡 + 共几条」，400 词的队列（约 60KB）不再每次切页都跨线程搬一遍。
- **大列表增量渲染**：今日待练（最多约 990 项）、错词本（最多 480 项）首屏只渲染 30 条，下滑「加载更多」追加，不再一次性铺满页面；口语页队列超过 20 条时，进度指示从「每个条目一个圆点」改为「进度条 + 3 / 480」，节点数从上百个降到 2 个。
- **写入合并（延迟落盘）**：评一张卡原来要同步重写 progress/stats/daily 三个 key，等于每点一下都往 Storage 塞几十 KB（学满 480 词时单张进度表约 34KB）。现在热路径改成「内存立即生效、磁盘攒一批再落」，读永远读内存所以看不到延迟；1.5s 空闲、攒够 12 次、页面 `onHide`/`onUnload`、App 进后台、导入导出前都会强制落盘。实测连评 20 张卡从 60 次写 / 1.8MB 降到 15 次写 / 240KB。
- **进度不再清零**：口语、测验、学习三页切走再回来接着上次的位置练，不会重新随机题目、不会把「做到第 87 张」打回第 1 张（队列指纹没变就沿用，变了才重建）。
- **逐词高亮只在词边界唤醒**：原来每 60ms 轮询一次，3 秒音频要醒 50 次；现在按时间表算下一个词边界，唤醒次数≈词数（实测一段 4 词音频从 50 次降到 5 次）。换词时也只 setData 一个下标（16B），不再重发整个 token 数组（长句 447B）。高亮的**起点跟着真正出声的那一刻**（`InnerAudioContext.onPlay`），不是点下去就跑——网络源第一次要下载几百毫秒，以前字幕会先跑完、声音后到。
- **首页 `onShow` 不再空转**：`storage.init()` 改为按档案幂等 + 老数据迁移打一次性标记，重复调用 0 次同步读（原来每次回首页 16 次）。
- 缓存正确性有单元测试覆盖（读次数下降、写后即时可见、失效后能发现外部改动、延迟落盘的 flush 时机与攒批阈值、`init` 幂等、读出的对象是拷贝改不脏缓存）。
- **文件配额统一记账**：微信给的 10MB 本地文件额度是**录音和发音缓存共用的一份**，以前两个模块各自按「整份都归自己」估算（录音 8MB + 缓存 3MB = 11MB），超出的部分谁后写谁静默失败。现在额度集中写在 `utils/file-budget.js`（录音 5MB / 在线发音缓存 1.5MB / 离线音频副本 2MB，另留 1.5MB 给临时文件）。
- **录音按体积+条数双淘汰**：录音保存时先按 30 条、再按总量 5MB 从最旧的删；万一还是写不进去，先删最旧一条重试，仍不行就去压发音缓存（保留四分之一额度）再试一次，最后才如实告诉用户「录音没存下来」。牺牲顺序是有意为之：录音是用户自己录的资产，缓存随时能重新下载。
- **异常兜底**：`app.js` 挂了 `onError` / `onUnhandledRejection` / `onPageNotFound`，页面出错不再静默白屏，页面路径失效会自动回首页；本地写入失败（空间满等）会明确提示用户先备份，不会让你以为进度已保存。

## 给家人朋友用（多人场景）

## 关于发音客观评分（进阶可选，现阶段可忽略）

默认使用**自评**（再练练/基本流利/很流利），导入即可用、无需任何后台配置。

**客观发音分**现在接的是**智聆口语评测**插件（`ihearing-eval`，provider `wx63d6102e26f0a3f8`）：它自己做声学评测，直接返回发音准确度/流畅度/完整度、每个词是「读错/漏读/多读/生词」，**以及每个音素（θ / ð / s / z 这类）的独立准确度**。所以「需要练的词」会直接点名：`think（读错 · θ 34 分）`，不用你猜是哪个音没读对。比原来「同声传译转文字再算相似度」准得多——后者测的其实是识别器猜没猜对，不是发音好不好。

⚠️ **插件需要先在小程序后台申请添加**（设置 → 第三方设置 → 插件管理 → 搜索「智聆口语评测」），否则 `app.json` 里的声明会让项目编译报错。如果暂时不想加，删掉 `app.json` 里的 `plugins` 块即可，代码自动降级为纯自评，功能不受影响。详见 **[智聆评测接入说明.md](智聆评测接入说明.md)**。

## AI 查词的审核流程（三步，全程不用服务器）

AI 只当草稿纸：**小程序里的 AI 查词是「当场答、不落库」**，机器生成的释义永远不会自己进用户手机。
想把它变成正式词条，走这三步：

```bash
# 1. 打开审核台（本地双击即可，纯静态页，不需要部署）
open tools/review.html          # macOS
xdg-open tools/review.html      # Linux
#    粘一串词 → 「问 AI」→ 逐条看词形/音标/释义/例句 → 点「收录」/「丢弃」→「导出收录的词」

# 2. 合并进词库（自动查重、自动编号、拒绝空字段）
node tools/merge-ai-words.js ai-words-reviewed.json --category 财务 --dry   # 先看要收哪几条
node tools/merge-ai-words.js ai-words-reviewed.json --category 财务

# 3. 校验后推送（CI 跑测试 + 自动发布在线词库，约 40 秒）
node tools/validate.js && node tests/run-tests.js && git push
```

- **审核台**（`tools/review.html`）直接调 Worker 的 `/lookup`，逐条展示 AI 结果，点「收录」才进导出 JSON；页面自己不做任何持久化。
- **合并脚本**（`tools/merge-ai-words.js`）做四件守门：词形/释义非空、长度合理、不含 HTML 角括号、**和现有词库去重（词形不分大小写；释义重复也拒——选择题里两个同义选项等于两个正确答案）**。
- 合并完自己看一眼 `git diff`，词条错了改掉再推；音频不在这里生成（英语单词走在线发音，日语新词要 `node tools/gen-audio.py --lang ja`）。

**为什么不自动收录**：AI 偶尔会把近义词、词性、搭配写错，而且错得很像对的。词库是产品的底座，错了就是「教会用户一个错的用法」，比没有更糟。

## 后续可选项（以及为什么现在没做）

下面几件事都评估过，当前统一判定是「收益不可测、风险可测」，留到真有需要时再做：

1. **句子调度的细节**：句子已经进 FSRS（`utils/sentence-progress.js`，10 题里有 3 题是句子题），但「再练练」和机评自动记分用的是同一套入口，暂时没有区分「跟读练了几次」和「测验答对几次」的权重；想更准可以按来源给不同初始难度。
2. **统计页 canvas 脏检查**：统计页每次 `onShow` 都重画两张图（约 53 处 `ctx.` 调用）。加「数据指纹没变就跳过重绘」能省一次重绘，但统计页不是热路径（切 tab 时一次几十毫秒），而脏检查写错的后果是「数据变了没重画」——比省下的那点时间更糟。
3. **音频体积是流量成本，不是包体积了**：mp3 已全部移出代码包（`audio-src/` + CDN），主包只剩代码 467KB。加素材只需注意别让用户首次听一句等太久——单条 5–7KB，16kbps 已是压过的码率。

4. **主包已瘦身到 467KB**：英语音频进分包后，主包只剩代码，冷启动只需要下 ~470KB。「代码质量」扫描的四项（主包 <1.5M、组件按需注入、音频资源 <200K、无未使用插件）都已处理：`app.json` 加了 `"lazyCodeLoading": "requiredComponents"`，`requirePlugin('ihearing-eval')` 改成字面量（扫描器只认字面量）。
4. **语言码收敛**：`getLangMeta()` 已有 `voice`（`en_US`/`ja_JP`，给音频链用）和 `tts`（`en-US`，给同声传译插件用），但还有 3 处页面仍手写 `lang === 'ja' ? 'ja_JP' : 'en_US'`。纯写法问题，不影响功能，下次动这几个页面时顺手换掉即可。

## 进阶（可选）：启用发音客观评分

`app.json` 里已经声明了智聆插件，**但插件本体要先在后台申请添加，否则编译会报「找不到插件」**：

1. 登录微信公众平台 → 设置 → 第三方设置 → 插件管理 → 添加插件
2. 搜索「智聆口语评测」，或直接搜 AppID `wx63d6102e26f0a3f8`，申请并等待通过
3. 通过后回开发者工具重新编译，`utils/speech-score.js` 会自动检测到插件并启用评测，**无需改其他代码**
4. 不想加插件：删掉 `app.json` 的 `plugins` 块即可，所有功能照常，只是没有客观分数

配额默认 2000 次/小时/小程序；评测只支持中英文，日语自动走自评。完整说明见 **[智聆评测接入说明.md](智聆评测接入说明.md)**。
